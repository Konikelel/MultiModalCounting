Fairness rule

Notebook structure and ownership

Preserve the supplied cell order and function interfaces. Every owner supplies code, tests, evidence, and a short interpretation—not code alone.

02 · NOTEBOOK
Member 1

Setup + Task 1

Image encoder and raw baseline runs

Environment, model setup, and encode_image

  • Use the required Python 3.9 environment and package versions.
  • Verify checkpoint SHA-256 and zero key mismatches.
  • Record Python, PyTorch, CUDA, CPU/GPU, and model paths.
  • Accept both (B,3,H,W) and lists of (3,H,W).
  • Create a CountGD NestedTensor on the model device.
  • Run model.backbone under inference mode.
  • Run model.combine_features.
  • Return feature list, positional encodings, and combined map.
  • Print input, mask, multi-scale, position, and combined shapes.
  • Visualize channel-wise mean activation at every scale.
  • Run and time the four required baseline forward passes.
  • Save raw predictions for Members 3 and 4.
Member 2

Task 2 + Task 6 sensitivity

Text encoding and changed prompts

encode_text and phrase-aware prompt evaluation

  • Tokenize a non-empty caption batch with longest-sequence padding.
  • Generate special-token attention masks and position IDs.
  • Apply max_text_len truncation consistently.
  • Run BERT and model.feat_map under inference mode.
  • Return encoded text, valid-token mask, positions, and attention metadata.
  • Use unequal caption lengths to demonstrate real padding.
  • Create a token/ID/mask/position table and mask visualization.
  • Implement phrase_token_indices.
  • Exclude special tokens, padding, and punctuation.
  • Implement confidence-product phrase post-processing at 0.50.
  • Run fresh inference for “man” and “yellow car”.
  • Compare changed and original prompts using the same phrase rule.
Member 3

Task 3 + visual analysis

ROIAlign, plots, ablation, failure

extract_exemplar_tokens and qualitative evidence

  • Validate (B,D,H,W) combined features.
  • Validate one finite, positive-area (N,4) box tensor per image.
  • Enforce resized pixel-space xyxy coordinates.
  • Use output_size=(1,1), spatial_scale=1/8, and aligned=True.
  • Return exemplar tokens shaped (B,N,D).
  • Overlay the original/resized exemplar box on the car image.
  • Demonstrate and explain the normalized-box error.
  • Create the four-case baseline localization figure.
  • Create the changed-prompt localization figure.
  • Compare car text-only, exemplar-only, and multimodal outputs.
  • Select one failure only after inspecting live evidence.
  • Annotate the failure and propose a measured, cautious explanation.
Member 4

Tasks 4–5 + validation

Similarity, Top-K, quantitative results

calculate_similarity_matrix, select_topk, and result checks

  • Validate query (B,N,D), prompt (B,T,D), and mask (B,T).
  • Compute batched query–prompt dot products.
  • Replace invalid prompt columns with -inf.
  • Add a deterministic test containing a genuinely padded column.
  • Create a readable, token-labelled similarity heatmap.
  • Reduce each proposal to its strongest prompt score and ID.
  • Run torch.topk over proposals and gather prompt IDs.
  • Verify descending scores and exact proposal/prompt indexing.
  • Explain that Top-K is not non-maximum suppression.
  • Validate standard post-processing at baseline threshold 0.23.
  • Check raw output shapes (900,256) and (900,4).
  • Compile counts, errors, score summaries, and runtime tables.

Data hand-offs

Member 1 · Raw evidence Features, positions, raw logits, boxes, and timings.
Member 2 · Prompt evidence Text masks, phrase indices, and changed-prompt outputs.
Member 4 · Quantitative results Post-processed counts, errors, scores, and ranked proposals.
Member 3 · Visual analysis Localization plots, ablation comparison, and failure figure.
Required threshold separation

The four official baselines use the CountGD threshold 0.23. The changed-prompt phrase-product study uses its separately specified threshold 0.50. Every table and figure must name which rule it uses.

Presentation design rule

Each slide should make one claim and show its evidence. Do not paste notebook code or read tables aloud. Keep complete token tables, shape details, box conversion, and Top-K rows as Q&A notes or appendix slides only if the instructor permits appendix slides.

Shared workflow

Use one results freeze point so the notebook, report, and slides never describe different runs.

06 · SEQUENCE

Prepare environments

All members install the official environment and assets. Member 1 records the canonical setup evidence.

Implement owned cells

Each member works in a separate notebook copy and preserves supplied interfaces and cell order.

Run local checks

Each owner completes shape assertions, positive tests, negative tests, outputs, and interpretation.

Integrate as a group

Insert owned cells into one clean master notebook during a shared session; no solo merge owner.

Execute live model

Run baselines and fresh changed prompts; synchronize timings where needed; save raw outputs.

Freeze results

Members 3–4 finalize figures and tables. Group verifies counts, thresholds, and failure evidence.

Write assigned sections

Use the frozen outputs only. Insert figure/table references and avoid unsupported explanations.

Build and rehearse slides

Reuse simplified report visuals, rehearse transitions, and reduce the talk to no more than ten minutes.

Final clean run

Clear stale outputs, run top to bottom, complete four review passes, rename all three submission files.

Definition of done

Every member must finish all five contribution types below before their allocation is complete.
